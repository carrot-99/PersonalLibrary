# 04. 画面設計

## 4.1 画面レイアウト

`client/Index.html` が唯一の HTML ページで、以下の領域で構成されます。

```
┌──────────┬──────────────────────────────────────────────────────────┐
│          │ 🥕 にんじん図書館   [作品・シリーズ・箱を検索]   [通知エリア]  │
│ サイド    ├──────────────────────────────────────────────────────────┤
│ メニュー  │                                                          │
│ (Navbar) │ コンテンツ領域（tabContent）                              │
│          │   選択中の View を 1 つだけ表示                            │
│ 登録      │   （サマリー・最近追加した漫画はホームの中に置く。4.8.0.1）   │
│          │                                                          │
│ 一覧・管理│                                                          │
└──────────┴──────────────────────────────────────────────────────────┘
  （スマホ幅では画面下部に下部タブバー .bottom-nav）
```

| 領域 | 要素 ID / クラス | 内容 |
|---|---|---|
| メニュー開閉ボタン | `#menuToggle` | タブレット幅（721〜1100px）だけ表示。サイドメニューを開閉（スマホ幅は下部タブバーの [メニュー]） |
| サイドメニュー | `#sideMenu` | `Navbar.html` を埋め込み |
| 検索欄 | `#globalSearchInput` | 作品・シリーズ・箱（datalist。シリーズは「シリーズ: 名前」、箱は「箱: ID : 場所」）を検索し、それぞれの詳細（`TitleView` / `SeriesView` / `BoxView`）を開く（`runGlobalSearch`。開く前の画面へ [← 戻る] で戻れる）。書籍・アニメどちらのモードでも表示。作品 → シリーズ → 箱の順に探し、完全一致、なければ部分一致が 1 件のときに確定。複数・0 件はエラー通知（[5.11](05_client_common.md#511-上部バーの検索)） |
| 通知エリア | `#globalNotification` | 成功（4 秒）・エラー（6 秒）で自動消去 |
| サマリーパネル | `.top-summary-panel` | ホーム（`HomeView`）の中に置く（PC は 6 項目を 1 段、それより狭い幅は 3 列・2 段）。書籍モードは所蔵冊数 / 漫画所蔵冊数 / ラノベ所蔵冊数 / 登録作品数 / 積読（未読の冊数）/ 最新登録（`getLibrarySummary`）、アニメモードは視聴のサマリー（4.2） |
| コンテンツ領域 | `#tabContent` | 各 View |
| 最近追加 | `#globalRecentLibraryTable` | ホーム（書籍モード）の欄の 1 枚（`.recent-history-panel`）。作品名・巻数（`getRecentLibrary`） |
| 下部タブバー | `.bottom-nav` | スマホ幅だけ表示（下表） |

サマリーパネルと最近追加は**ホームだけに表示し、ホームを開くたびに再取得**します（前回の結果をすぐ表示して裏で取り直す。[5.2](05_client_common.md#取得結果のキャッシュ--callgascached)）。どちらもホームの中にあるので、ほかの画面では表示も取得もしません。

一覧画面（シリーズ・作品・箱・書籍・アニメ）も、開いたら前回の一覧をすぐ表示し、裏で取り直している間は見出しの横に「最新の情報を確認中...」を出します。インライン編集の保存・削除は、取り直しを待たずに行を書き換えて（消して）表示します。

### レスポンシブ

| 画面幅 | レイアウト |
|---|---|
| 1101px 以上（PC） | サイドメニュー常時表示（☰ なし） |
| 721〜1100px（タブレット） | ☰ ボタンでサイドメニュー開閉（外側の暗幕タップでも閉じる）、縦積み、サマリー 3 列 |
| 720px 以下（スマホ） | タッチ操作向けの専用レイアウト（下表） |

スマホ（720px 以下）の主な違い。スタイルは `Styles.html` 末尾の `@media (max-width: 720px)` にまとめ、他のルールより優先させています。

| 対象 | スマホでの表示 |
|---|---|
| 上部バー | タイトル・検索欄・通知エリアを画面上部に固定（スクロールしても表示）。検索欄は全幅。☰ は出さない |
| 下部タブバー | 画面下部に固定（`.bottom-nav`）。書籍モードは [🏠 ホーム] [📷 写真登録] [📅 発売予定] [📚 作品]、アニメモードは [🏠 ホーム] [▶️ 視聴中] [🗓️ 今期] [📺 一覧]、右端に [☰ メニュー]（サイドメニューの開閉）。表示中の画面のボタンを強調（`showTab` がサイドメニューと同じく `active` を付ける）。画面の下端はタブバーの分だけ余白を空ける |
| サイドメニュー | 下部タブバーの [メニュー] で開く。幅は画面の 86%（最大 340px）、下部タブバーの上まで、ボタン高さ 50px |
| サマリー | 3 列・2 段に圧縮 |
| 入力欄・ボタン | 文字 16px（iPhone の入力時ズームを防ぐ）、高さ 48px 以上。画面内の単独ボタン（[表示] [保存] [解析] 等）は全幅 |
| ツールバー | 見出しの下に全幅、ボタンを横並び・等幅（高さ 52px）。追加フォームは入力欄を 1 列に |
| 一覧（カード表示） | 一覧画面の表（`createListFilter` の表。クラス `card-list`）は **1 行を 1 枚のカード**で表示。各項目は「列名　値」の形（列名は `renderPagedTableDOM` がセルの `data-label` に入れる）で、2 列目（作品名・シリーズ名など）を太字に、空の項目は出さない。[編集] [削除] はカードの下に右寄せ。見出し行は並べ替えボタンの帯（「作品名 ⇅」などのボタンを折り返して並べる。並べ替えできない列・操作列は出さない）。シリーズ・作品・書籍の一覧では自動採番の ID を非表示（箱は BoxID を利用者が入力するため表示）。[編集]・ページングのボタンは 44〜48px |
| テーブル（一覧以外） | 詳細画面などの表は文字を省略せず折り返し、列幅は内容に合わせる |
| インライン編集 | カードのまま入力欄・選択欄をカードの幅いっぱいに表示（編集中のカードは左端が黄色）。入力欄には列名をプレースホルダー表示 |
| 写真から登録 | チェック・ボタン類を拡大、作品追加フォームは 1 列。[登録確定] は下部タブバーのすぐ上に固定（`position: sticky`） |

## 4.2 メニュー構成（`client/Navbar.html`）

サイドメニューの先頭に **[📚 書籍] / [📺 アニメ] の切り替え**があり、選んだほうのメニューだけを表示します（下表の「モード」列）。

| モード | グループ | ボタン | 表示 View | 色 |
|---|---|---|---|---|
| 共通 | （見出しなし。切り替えの直下） | 🏠 ホーム | `HomeView` | 青 |
| 書籍 | 登録 | 写真で確認・登録 | `PhotoImportView` | 紫 |
| | | 欲しい巻リスト | `WishListView` | |
| | | 発売予定 | `ReleaseView` | |
| | | おすすめ | `RecommendView` | |
| | 一覧・管理 | 作品一覧 | `TitleListView` | 緑 |
| | | 箱一覧 | `BoxListView` | |
| | | 書籍一覧 | `LibraryListView` | |
| アニメ | 視聴・登録 | 視聴中の一覧（＋登録） | `AnimeWatchingView` | ピンク |
| | | 今期のアニメ | `AnimeSeasonView` | |
| | 一覧・管理 | アニメ一覧 | `AnimeListView` | |
| 共通 | シリーズ（書籍・アニメ共通） | シリーズ一覧 | `SeriesListView` | 青 |

- ボタン押下で `showTab('<View>')` → `closeSidebar()`。
- 「共通」のグループはどちらのモードでも表示。ホーム・シリーズ一覧・シリーズの詳細（`COMMON_VIEW_IDS`）は開いてもモードを切り替えません（アニメモードのままシリーズを見られる）。
- モードを切り替えると、そのモードの最初の画面を開く（書籍: `PhotoImportView`、アニメ: `AnimeWatchingView`）。続けてメニューを選べるよう、切り替えではサイドメニューを閉じない。
- 書籍モードだけの表示: 所蔵サマリー・最近追加した漫画（どちらもホームのみ）。
- アニメモードだけの表示: アニメのサマリー（ホームのみ。視聴済・視聴中・視聴中断・視聴予定の期数、登録作品数、視聴話数の合計）。ホームを開いたとき（キャッシュ `animeData.summary`）とアニメ画面で `getAnimeData` を取得するたびに更新（`renderAnimeGlobalSummary`）。
- **初期表示はホーム（`HomeView`）**。モードは前回のもの（初回・保存できない環境では書籍）で、ブラウザの `localStorage` に保存。
- メニューの末尾に **配色**（[自動] / [☀ ライト] / [☾ ダーク]）。自動は OS の設定に合わせる。選んだ配色はこのブラウザに保存（[05 章 5.13](05_client_common.md#513-デザイントークンと配色)）。

## 4.3 画面遷移

メニューの各画面は直接切り替わります。作品・シリーズ・箱の**詳細画面（4.4）はメニューに置かず**、一覧や詳細の中の名前のリンク（下線付き）から ID を指定して開きます（`openTitleDetail` / `openSeriesDetail` / `openBoxDetail`）。

| リンク元 | リンク | 開く画面 |
|---|---|---|
| シリーズ一覧 | シリーズ名 | シリーズの詳細 |
| 作品一覧 | 作品名 ／ シリーズ | 作品の詳細 ／ シリーズの詳細 |
| 箱一覧 | BoxID・保管場所 | 箱の詳細 |
| 書籍一覧 | 作品名 ／ Box | 作品の詳細 ／ 箱の詳細 |
| シリーズの詳細 | 書籍の欄の作品名 | 作品の詳細（書籍モードに切り替わる） |
| 作品の詳細 | 所持状況の「シリーズ」 ／ 表の BoxID | シリーズの詳細 ／ 箱の詳細 |
| 箱の詳細 | 作品名 | 作品の詳細 |
| アニメ一覧（作品ごと） | シリーズ | シリーズの詳細（アニメモードのまま） |
| 上部バーの検索 | — | 作品・シリーズ・箱の詳細 |
| ホーム | 作品名（発売予定・未所持・欲しい巻）／ 各欄の見出しの「… →」 | 作品の詳細 ／ 発売予定・欲しい巻リスト・視聴中の一覧 |
| おすすめ | 「似ている手持ち」の作品名 | 作品の詳細 |

- リンクで開いた詳細画面には **[← 戻る]** を表示し、押すと開く前の画面（一覧、または前の詳細）を、そのときのモードで開き直します（最大 20 件までさかのぼれる）。一覧は絞り込み条件・並び順・ページを保ったまま再取得します。
- メニューから画面を開くと、戻る履歴は消えます（[← 戻る] は非表示）。
- 一覧の [編集] 中はリンクが入力欄に置き換わり、[取消] でリンクに戻ります。

## 4.4 詳細画面（作品・シリーズ・箱）

3 画面とも同じ構成です：[← 戻る]（4.3）＋ オートコンプリート入力と「表示」ボタン（横並びの `.detail-picker`）＋ 見出しと数字のまとめ（`.detail-hero`。`renderDetailHero`）＋ 欄（`.detail-panel`）。結果 0 件時は非表示。リンクから開いたときは入力欄に名前を入れて表示まで行います。入力欄で別の作品等を選んで [表示] することもできます。検索中はインラインローディングを表示します。

| 画面 | View / ファイル | 入力 | 結果列 | API |
|---|---|---|---|---|
| シリーズの詳細 | `SeriesView` / `series/SeriesView.html` | シリーズ名 `#seriesSelectInput` | 見出し（下記）＋ 書籍の欄とアニメの欄（下記） | `getSeriesOverview` |
| 作品の詳細 | `TitleView` / `title/TitleView.html` | 作品名 `#titleViewSelectInput` | 見出しと数字のまとめ・所持状況・巻の一覧（下記）＋ 巻, BoxID, 読書（巻数順。たたんだ欄 `#titleTableSection`） | `getTitleDetail` |
| 箱の詳細 | `BoxView` / `box/BoxView.html` | Box（`<ID> : <場所>`） `#boxViewSelectInput` | 見出し（下記）＋「📦 中の本」欄（集計＋ 作品名, 巻） | `getBoxOverview` |

- **Box・シリーズの集計**（`formatGroupSummaryLines` / `renderSummaryLines`。所持状況と同じ見た目）: 冊数（漫画・ラノベの内訳）、作品数、積読（未読の冊数。読書中があれば併記）、最終追加日。書籍がなければ「書籍は登録されていません」。箱の詳細は「📦 中の本」欄の先頭（`#boxSummary`）、シリーズの詳細は「📚 書籍」欄の先頭（`#seriesBookSummary`。作品数の後に「抜け」＝抜けのある作品の件数を追加）。
- **シリーズの詳細**（書籍・アニメ共通）: 「📚 書籍」欄（`#seriesBookSection`。集計と、作品名・種別・所持巻数・所持巻の表。作品がなければ「このシリーズの書籍は登録されていません」）と「📺 アニメ」欄（`#seriesAnimeSection`。まとめ＝期の件数と種別内訳・状況内訳・視聴話数の合計、期の表＝作品 / 期 / 種別 / 視聴済話数 / 状況。作品の登録順→期の順）。アニメモードではアニメの欄を先に表示します（旧アニメのシリーズ別検索 `AnimeSeriesView` は統合して廃止）。
- 画面を開き直すと、入力欄・結果テーブル・所持状況はクリアされます（リンク・[← 戻る] で開いたときは続けて表示）。
- 未選択（入力値に一致する候補なし）の場合: 「シリーズを選択してください」等のエラー通知。
- **シリーズ・箱の詳細の見出し**（`#seriesDetailHero` / `#boxDetailHero`）: シリーズ名（箱は BoxID と保管場所のバッジ）、漫画・ラノベの冊数のバッジ（`buildGroupTypeChips`）、数字のまとめ（`buildGroupStats`）＝ 冊数 ／ 作品 ／ 積読（なければ緑）／ 最終追加。シリーズは最終追加の代わりに 抜け（抜けのある作品の数。あれば黄色）／ アニメ（期の数）（`buildSeriesStats`）。
- **作品の詳細の見出し**（`#titleDetailHero`。`renderTitleHero`）: 作品名、種別・完結状態のバッジ、数字のまとめ 4 枚（`buildTitleStats`）＝ 所持（冊数）／ 抜け（巻数。あれば黄色、なければ緑）／ 積読（未読の冊数）／ 次の巻（完結済の作品は「全巻所持」か「抜けあり」）。スマホ幅は 2 列。
- **巻の一覧**（`#titleVolumeGrid`。`renderTitleVolumeGrid` / `buildTitleVolumeGrid`）: 1 巻から最大巻（所持・欲しい巻のうち最大）まで巻番号を並べ、読了（緑）／ 読書中（黄）／ 未読（青枠）／ 未所持（点線）／ 欲しい巻（ピンクの点線。所持している巻なら下線）で示す。数字以外の巻（特装版など）は後ろに並べる。欲しい巻は `getWishKeys` の取得後に描き直す。下に凡例。
- **作品の詳細の所持状況**（`#titleOwnershipSummary`）: シリーズ（シリーズの詳細へのリンク。シリーズ未設定なら行なし）、所持（冊数と巻の範囲）、抜け（1 巻から最大巻までの未所持巻。あれば強調表示）、次の巻（最大巻＋1）を表示。完結済の作品は「次の巻」の代わりに「抜けなく所持しています／抜けている巻があります」。本を登録している作品は読書状況「次は n巻（読書中）・積読 n冊」と [n巻を読了]（次に読む巻を読了にして表示し直す）、すべて読了なら「すべて読了」を追記（`appendTitleReadLine`。次に読む巻は `pickNextReadVolume`）。欲しい巻リストに登録がある場合は「欲しい巻 ★ 104, 107〜108巻」を追記（`appendTitleWishLine`）。
- 所持巻の表記（シリーズの詳細・作品一覧）: `1〜12巻, 上（抜け: 7巻）`。完結済で抜けがなければ `（完結・抜けなし）`、所持なしは `未所持`。数値以外の巻（`上`・`外伝` 等）は抜けの判定に含めません。
- 入力値の解決は `getAutocompleteValue()`（完全一致を優先し、部分一致は 1 件のときのみ採用。[05 章](05_client_common.md#55-オートコンプリート)参照）。部分一致が複数なら「作品を選択してください」等のエラー。

## 4.5 一覧・管理画面

シリーズ・作品・箱・書籍の一覧で、参照と管理（追加・インライン編集、書籍は削除）を 1 画面で行います（旧マスタ管理画面は統合して廃止）。タブ表示時に**全件を取得**し、絞り込み・並べ替え・ページング（1 ページ 20 件）は画面側で行います（[05 章 5.12 createListFilter](05_client_common.md#512-一覧の絞り込み並べ替え)）。

```
見出し        [＋ 追加] [⇄ 統合]  ← .view-header（見出しと .master-toolbar を左右に。[統合] はシリーズ一覧のみ）
┌ 追加フォーム ┐        ← 初期非表示。[＋ 追加] でトグル（他フォームは閉じる）。入力欄は横並び（.form-grid）
└─────────────┘
┌ 絞り込み欄 ┐          ← キーワード＋選択式、件数、[クリア]
└───────────┘
┌ 一覧テーブル ─────────┬──────────┐
│ ...                   │ [編集] ([削除]) │  ← 操作列
└───────────────────────┴──────────┘
« 前へ 1 2 3 … 次へ »
```

| 画面 | View / ファイル | 列 | API | 絞り込み（選択式） | キーワード対象 | 初期の並び |
|---|---|---|---|---|---|---|
| シリーズ一覧（書籍・アニメ共通） | `SeriesListView` | SeriesID, シリーズ名, 書籍（作品数）, 冊数, アニメ（期数）, 操作 | `getSeriesListWithCounts` | 書籍（あり・なし）/ アニメ（あり・なし） | ID・シリーズ名 | シリーズ名 昇順 |
| 作品一覧 | `TitleListView` | TitleID, 作品名, シリーズ, 種別, 完結, 所持巻（抜けを含む）, 操作 | `getTitleListWithOwnership` | 種別 / 完結 / 所持（抜けあり・抜けなし・未所持）/ シリーズ | 作品名・シリーズ名・所持巻 | 作品名 昇順 |
| 箱一覧 | `BoxListView` | BoxID, 保管場所, 冊数, 作品数, 操作 | `getBoxListWithCounts` | — | ID・保管場所 | BoxID 昇順 |
| 書籍一覧 | `LibraryListView` | ID, 作品名, 巻数, Box, 読書, 追加日, 操作 | `getLibraryListAll` | 読書（未読・読書中・読了）/ 種別 / Box / 追加月 | ID・作品名・巻数・Box・追加日 | 追加日 新しい順 |

- 表の上の絞り込み欄: キーワード（部分一致・大文字小文字無視）、選択式の絞り込み（選択肢は「すべて」＋データ中の値）、件数「n件 ／ 全m件」、[クリア]（条件があるときだけ表示）。
- **見出しをクリックすると並べ替え**（もう一度押すと逆順。▲▼ で表示）。作品一覧の「所持巻」は抜けの数→所持冊数の順、書籍一覧の「作品名」は作品名→巻数の順、「巻数」は数値の巻を数値順で並べます。
- 絞り込み条件・並び順は、他の画面へ移動して戻っても保持されます（再読込時はデータだけ入れ替え）。追加・編集・削除の後も一覧を再取得し、条件は保持します。
- 作品一覧の「所持」: 1 冊も登録がない＝未所持、1 巻から最大巻までに未所持の巻がある＝抜けあり、それ以外＝抜けなし（数値以外の巻は判定に含めない）。
- メニューから画面を開き直すと、追加フォームは閉じます（入力値は残ります）。

- **書籍一覧の読書状況のまとめて変更**: 表の上の「表示中の書籍を [読了▼] [にする]」で、キーワード・絞り込みに合う書籍（全ページ分。すでにその状況の本は除く）をまとめて変更（`applyLibraryReadBulk` → `setReadStatusWeb`）。1 回目で「n冊を「読了」にする（もう一度押して確定）」になり、4 秒以内にもう一度押すと確定。例: 作品名で絞り込んで [読了] [にする] で、その作品をまとめて読了にする。

### 編集・削除

- 各行の [編集] でインライン編集（[05 章 5.7](05_client_common.md#57-インライン編集)）。ID 列と集計列（所持巻・追加日）は編集できません。
- 作品の種別（`漫画` / `ラノベ`）・完結（`連載中` / `完結済` / `未完結`）は選択式。
- 書籍・作品・シリーズ・Box の各行に [削除]。1 回目で「本当に削除」に変わり、4 秒以内にもう一度押すと削除。
- 作品・シリーズ・Box は、使われていると削除できません（エラー通知で件数と対処を表示）。作品は書籍があるとき（先に書籍一覧で書籍を削除）、シリーズは作品・アニメ作品があるとき（統合で別のシリーズにまとめられる）、Box は書籍が入っているとき（書籍を別の Box に移すか削除）。書籍のない作品は、その作品の欲しい巻・発売情報も一緒に削除します。
- PC・タブレット（721px 以上）では表ごとに列幅を指定（合計 100%）。操作列は [保存] [取消]・[編集] [削除] を折り返さずに並べる。
- シリーズは同じ名前を、作品は同じ名前・同じ種別を登録・更新できません（エラー通知）。作品名が同じでも種別（漫画／ラノベ）が違えば登録できます。
- 同じ名前の作品は、作品を選ぶすべての入力欄・書籍の一覧で「作品名（種別）」と表示されます。作品名だけを入力した場合は候補が複数となり、選択を求めます。
- 追加・更新成功時は一覧の再読込と、各画面の選択肢（`refreshMasterData`）を更新（書籍は最近追加・サマリーを再読込）。

## 4.7 写真で確認・登録画面

`PhotoImportView`（`client/library/PhotoImportView.html`）。**初期表示画面**で、メニューの「登録」グループから開きます。ロジックは `client/library/PhotoImport.html`、表示時の処理は `loadPhotoImportView()`。
画面は常時表示のパネル（`#photoImportPanel`、クラス `photo-import-panel`）1 つで構成します。一覧・管理画面の `.master-form` と違い、画面切替時（`resetViewState`）に閉じられません。
本の表紙・背表紙を撮って**持っている巻かを確認（確認モード）**し、持っていない本は**そのまま登録（登録モード）**できます。書店での所持確認と、購入後の登録を 1 画面で行います。
画面を開くたびに前回の写真・解析結果・登録結果をクリアします（解析・登録の処理中は残します）。

画面の上に**手順の表示**（`#photoImportSteps`。1 写真を選ぶ → 2 所持を確認 → 3 未所持を登録 → 4 完了）を置き、今の段階を強調、済んだ段階に ✓ を付けます（`updatePhotoImportSteps`。段階は `getPhotoImportStep`: 読み取り結果を表示中なら確認モードで 2・登録モードで 3、結果表示があれば 4、それ以外は 1）。スマホ幅では番号の下に名前を出します。

```
① 写真選択（最大5枚）→ サムネイル表示（タップで拡大ビューア）
② [チェック] → analyzeBookSpines（数十秒かかることがある。インラインローディング表示）
③ 確認モード: 1 冊 = 1 カードで所持チェックの判定を表示。上部に「n冊中 所持済み x冊 ／ 未所持 y冊」
     作品・巻数の読み取り違いはカード内の入力欄で修正（即時に再判定）
     マスタにない作品は [作品を追加] から作品（＋必要ならシリーズ）を追加できる
     ここで終われば登録しない（書店での確認用）
④ [未所持の本を登録する（n冊）] → 登録モード
     所持済みの本は非表示・登録対象外、未所持の本のみチェック ON
     作品・巻数・Box を確認・修正。マスタにない作品は [作品を追加]、必要に応じて [最終巻]
     [確認結果に戻る] で確認モードへ
⑤ [登録確定（n件）] → bulkAddLibraryFromPhoto → 結果表示
```

モードは `photoImportState.mode`（`check` / `register`）で、パネルのクラス `is-check-mode` により表示を切り替えます。登録用の要素（チェック・Box・状態・最終巻・一括Box・登録確定）はクラス `register-only`（[作品を追加] は両モードで表示）、[未所持の本を登録する] は `check-only`。

### 行の状態判定（`getPhotoImportStatus`）

上から順に判定します。

| 順 | 条件 | 状態 | 説明 |
|---|---|---|---|
| 1 | 作品未選択 | マスタ未登録 | 作品マスタに無い作品です（自動作成しません） |
| 2 | 巻数が空 | 要確認 | 巻数を入力してください |
| 3 | 巻数が不正、または 2 巻以上 | 入力エラー | 巻数は1つだけ入力してください |
| 4 | 要確認フラグあり | 要確認 | 作品・巻数を確認して「OK」を押してください |
| 5 | Box 未選択 | 入力エラー | Boxを選択してください |
| 6 | 登録済み（`existingKeys`）、またはチェック済みの前の行と同じ作品・巻 | 重複 | 同じ作品・巻数が登録済みです |
| 7 | 上記以外 | 照合済み | 登録可能 |

要確認フラグは、照合結果が `exact` 以外、または AI が `uncertain` を返した行で ON になります。作品・巻数を編集するか [OK] で OFF になります。

### 所持チェックの判定（`getPhotoImportVerdict`）

登録済みの巻（`existingKeys`）と、この一覧の同じ作品の未所持の巻（確認モードでは全行＝一緒に買うものとして扱う、登録モードではチェック済みの行）を合わせて判定します。**登録可否には影響しません**。

| 判定 | 条件 | 表示例 | 色 |
|---|---|---|---|
| 所持済み | 登録済みの巻 | 所持: 1〜103巻 | 緑 |
| 未所持・続きの巻 | 1 巻からその巻の前まで抜けがない | この一覧の104巻と合わせて続きになります ／ 所持: 1〜103巻 | 青 |
| 未所持・抜けていた巻 | 所持済みの最大巻より前 | 抜けている巻を埋められます ／ 所持: … | 青 |
| 未所持・間が飛ぶ | 1 巻からその巻の前までに未所持の巻がある | 6〜7巻が未所持です ／ 所持: … | 黄 |
| 未所持の作品 | 作品マスタに無い、または 1 冊も所持していない | 作品マスタに無い作品です | 灰 |
| 巻数不明 | 巻数を読み取れない | 所持: … | 灰 |

- 作品が特定でき、要確認フラグが ON の場合は「要確認（読み取りがあいまいです）」を付けます。
- 欲しい巻リストにある巻は、説明の先頭に「★欲しい巻リストにあります」を付けます。
- 作品・巻数・チェックを変えると全カードを即時に再判定します。確認モードで巻数を直して所持済みでなくなった本は、登録モードに表示されます。

### 作品追加後の動き

追加した作品を当該行に設定し、**同じ読み取り作品名で作品未選択の他の行**にも同じ作品を設定します（他の行は AI が `uncertain` の場合のみ要確認）。各画面の選択肢も再構築します（`refreshMasterData`）。

### 登録確定後の動き

- 登録できた行は一覧から消し、重複と判定された行は登録済みとして扱います。
- 対応が必要な行（チェック済みで重複以外）が残っていなければ、写真と一覧をクリアします。
- 1 件以上登録できた場合は、最近追加・サマリーを再読込します（書籍一覧は画面を開いたときに再取得）。

## 4.8.0.1 ホーム画面

`HomeView`（`client/home/HomeView.html`）。起動時に開く書籍・アニメ共通の画面で、メニューの「🏠 ホーム」からも開きます。ロジックは `client/home/Home.html`、表示時の処理は `loadHomeView()`（`getHomeDataWeb` を `callGASCached` で取得。前回の結果をすぐ表示して取り直す）。

上から、サマリー（4.1）、発売情報の状況、欄のパネルの順に並べます。各欄は 1 枚のパネル（`.home-section`）で、見出しにアイコン・件数・各画面へのリンク、上端の色で欄を見分けます（積読 緑・発売 水色・発売済未所持 橙・欲しい巻／視聴中 ピンク・最近追加 青）。パネルは幅に合わせて並べます（PC 幅で 2 列）。パネルの中の作品ごとの行は枠を付けず、区切り線で並べます。

| 欄 | 要素 | 内容 |
|---|---|---|
| 積読 | `#homeReading` | 未読・読書中の巻がある作品（読書中の作品が先、その後は最後に登録した日の新しい順。3.9.5 `getUnreadSummary`）。種別＋作品名・未読と読書中の巻の範囲・「読書中」と、[n巻を読了]（次に読む巻を読了にして取り直す）。件数は「未読 n冊・読書中 m冊」。見出しの右から書籍一覧へ |
| 状況 | `#homeReleaseStatus` | 「発売情報の最終取得: 日時」。楽天のアプリ ID 未設定・読み込み失敗はその旨 |
| 今週の発売 | `#homeWeek` | 今日から 7 日以内に発売の巻（3.9.4 `splitHomeReleases`）。各行は発売予定画面と同じ（日付 / 種別＋作品名＋巻 / [欲しい巻に追加] または「欲しい巻に追加済」） |
| 今月の発売 | `#homeMonth` | 今週以外で今月中に発売の巻（「11月下旬」なども）。件数の横に来月以降の冊数 |
| 発売済・未所持 | `#homeUnowned` | 作品ごとに巻の範囲と [n冊を欲しい巻に追加]。「完結済みかも」の作品は出さない（発売予定画面で見る） |
| 欲しい巻リスト | `#homeWishes` | 作品ごとに巻の範囲（最近追加した作品が先。`groupHomeWishes`） |
| 視聴中のアニメ | `#homeWatching` | 期名（作品名）と「N話まで」（最近更新した順）。件数の横に視聴予定の件数 |
| 最近追加した漫画 | `#globalRecentLibraryTable` | 書籍モードのみ。作品名・巻数（最大 10 件。たためない） |

- 積読・発売済・未所持・欲しい巻・視聴中は最大 8 件（`HOME_LIST_LIMIT`）で、超えた分は「ほか n 作品」。
- 各欄は見出し（▾ / ▸）を押すとたためる（`<details>`。スマホで行が多いとき用）。たたんだ欄はこのブラウザの `localStorage`（`personalLibrary.homeClosedSections`）に保存し、次に開いたときもたたんだまま（`setupHomeSections`）。たたんでも見出しの件数は表示する。
- 各欄の見出しの右の「発売予定 →」などで、それぞれの画面を開く（押しても欄は開閉しない）。
- [欲しい巻に追加] の後はホームを取り直す（`addReleaseToWish` の `onAdded`）。

## 4.8.1 アニメ画面

メニューを「アニメ」モードに切り替えると表示。ファイルは `client/anime/`、ロジックは `Anime.html`。書籍の画面とは独立しており、共通なのはシリーズ（`M_Series`）のみ。書籍の所蔵サマリー・最近追加した漫画・作品名検索は表示しません。

データは画面を開くたびに `getAnimeData()` で全件取得し（`loadAnimeData`）、絞り込みはクライアント側で行います。

### 視聴中の一覧（`AnimeWatchingView`）

| 区分 | 内容 |
|---|---|
| 視聴中 | 状況が `視聴中` の期をカード表示（最近更新した順）。期名・作品名（期名と違う場合）・種別・「N話まで視聴」。[+1話]（話数 +1）、[視聴済にする]、[中断]（`視聴中断`）で `updateAnimeWatch` を呼び、一覧を再読込 |
| 視聴予定 | 状況が `視聴予定` の期（登録順）。[視聴開始] で `視聴中` に変更 |
| 登録 | 上部の [＋ アニメを登録] で登録フォーム（`#animeEntryForm`）を開閉（下記「アニメ登録」） |

### 今期のアニメ（`AnimeSeasonView`）

Annict から期の作品を取得して一覧表示し、登録につなげます（`getCurrentSeasonAnimeWeb`。サーバー側で 6 時間キャッシュ）。メニューから開くと今期を表示します。

| 区分 | 内容 |
|---|---|
| 期の移動 | [◀ 前の期] / [次の期 ▶] で前後の期に移る（Annict の期はその期に始まった作品なので、前の期から続く作品は前の期で確認する）。[最新の情報を取得] はキャッシュを使わず Annict から取り直す |
| まとめ | 「N作品（未登録 M件）・Annict から取得: 日時」 |
| 一覧（`animeSeasonTable`、`createListFilter`、50 件ずつ） | タイトル（Annict の作品ページへのリンク） / 種別 / 話数（全話数） / 視聴者数（Annict。スマホ幅では非表示） / 登録（`未登録` または登録済みの期の状況。状況が空なら `登録済`） / 操作。絞り込みはキーワード（タイトル）・種別・登録。初期は視聴者数の多い順 |
| 登録 | 未登録の行の [登録] で、視聴中の一覧の登録フォーム（`#animeEntryForm`）をこの画面（`#animeSeasonEntryHost`）へ移して開く（`openAnimeEntryFromSeason`）。作品名＝候補（`suggestedAnimeName`）、期名＝Annict のタイトル、種別＝Annict の種別、視聴済話数＝空欄、状況＝`視聴予定` を入れ、フォーム上部に「Annict の「…」（TV・全12話）から入力しました」と表示（`#animeEntrySource`）。内容を確認・修正して [登録する] で登録。登録後はフォームを閉じて一覧を再読込（登録欄が状況に変わる） |

### アニメ一覧（`AnimeListView`）

上部の [期ごと] / [作品ごと] で表示単位を切り替えます（選択は画面を移っても保持）。どちらも書籍の一覧と同じ `createListFilter` で、見出しクリックで並べ替え、各行の [編集] でインライン編集します。追加は視聴中の一覧の [＋ アニメを登録] から行うため [追加] はありません（旧アニメ作品マスタ管理・アニメ期マスタ管理は統合して廃止）。

| 表示 | 列 | 絞り込み | 編集（保存先） |
|---|---|---|---|
| 期ごと（`animeListTable`、30 件ずつ） | 作品 / 期 / 種別 / 話数 / 状況 / 更新日 / 操作 | キーワード（作品・期・シリーズ名）、状況・種別・シリーズ。初期は作品名順 | 作品・期名・種別（選択）・話数・状況（選択）を `updateAnimeSeasonMaster`。作品を変えるとその期を別の作品に付け替え。各行に [削除]（2 回押しで確定、`deleteAnimeSeason`） |
| 作品ごと（`animeWorkListTable`、30 件ずつ） | 作品名 / シリーズ / 期（期の数） / 視聴話数（合計） / 操作 | キーワード（作品名・シリーズ名）、シリーズ。初期は作品名順 | 作品名・シリーズを `updateAnimeMaster`（シリーズは既存の名前のみ、空欄可） |

視聴中断の期を探すときは、期ごとで状況を絞り込みます。

### アニメ登録（視聴中の一覧の [＋ アニメを登録]、今期のアニメの [登録]）

旧「アニメ登録」画面（`AnimeEntryView`）は視聴中の一覧に統合して廃止しました。フォームは初期非表示で、メニューから画面を開き直すと閉じます。フォームは 1 つだけで、今期のアニメの [登録] ではその画面へ移して使い、視聴中の一覧を開くと戻します（`placeAnimeEntryForm`。移したときはフォームを閉じる）。登録後の再読込は開いた画面のもの（`animeEntryOnSaved`）。

| 項目 | 要素 | 備考 |
|---|---|---|
| 作品名 | `#animeEntryAnimeInput` | 登録済み作品を候補表示。一致すれば「登録済みの作品に期を追加」、しなければ「新しい作品として登録」と表示（`syncAnimeEntrySeries`） |
| シリーズ | `#animeEntrySeriesInput` | 新しい作品のときだけ表示。全シリーズ（書籍と共通）を候補表示。空欄なら作品名と同じシリーズ。未登録のシリーズ名は新規作成 |
| 期名 | `#animeEntrySeasonInput` | 空欄なら作品名 |
| 種別 | `#animeEntryType` | TV / OVA / 劇場版 / その他 |
| 視聴済話数 | `#animeEntryEpisodesInput` | 空欄可 |
| 状況 | `#animeEntryStatus` | 初期値 `視聴中` |

[登録する] で `addAnimeSeasonWeb`。成功後は期名・話数・シリーズ欄をクリア（作品名は残す）し、フォームを開いたまま視聴中・視聴予定のカードを再読込（続けて登録できる。今期のアニメから開いたときはフォームを閉じて今期のアニメを再読込）。書籍側の選択肢も再読込（`refreshMasterData`。シリーズが増えた場合のため）。
