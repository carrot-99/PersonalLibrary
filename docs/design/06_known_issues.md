## 6.2 仕様上の注意・リスク（R）

| ID | 優先度 | 内容 | 対応案 |
|   |   |   |   |
| R 10 | 低 | 写真から登録の作品照合はリクエストごとに全作品との類似度を総当たりで計算し、AI へも最大 1500 件の作品名を送る。作品数の増加で処理時間と API 費用が増える | 作品数が増えたら候補の絞り込み（読み・先頭文字など）を検討 |
| R 11 | 低 | `ANTHROPIC_API_KEY` はスクリプトプロパティに平文で保存される。スクリプトの編集権限を持つユーザーは閲覧可能 | 編集者を本人に限定する運用を維持。キー漏えい時は Anthropic Console で失効・再発行 |
| R 12 | 低 | 写真の解析（`UrlFetchApp`）は Apps Script の外部通信の時間制限を受ける。写真 5 枚・解析の深さ `medium` で時間切れになる可能性がある（未発生） | 時間切れが出たら写真を分けて解析する、`ANTHROPIC_EFFORT` を `low` にする、または写真ごとに順番に解析する方式に変更 |
| R 13 | 低 | 書籍一覧は絞り込みのため全件を読み込む（`getLibraryListAll`）。数千冊程度までは問題ないが、それ以上で表示が遅くなる | 件数が増えたらサーバー側で絞り込み・ページングする方式に変更 |
| R 14 | 中 | 一覧画面（シリーズ・作品・箱・書籍・アニメ）の表示が遅い。画面を開くたび・編集の保存のたびにスプレッドシートから全件を取り直している | 取得結果のキャッシュ（クライアント側の保持や `CacheService`）、保存時は該当行だけ差し替える、表示を先に出して裏で再取得する、などを検討 |
| R 15 | 低 | 一覧の列幅が内容によって変わり、ページ移動や編集で表がずれる。現在は PC・タブレット幅でだけ表ごとに % で指定 | 各列を適切な幅で固定する（`table layout: fixed` と列ごとの幅指定、スマホ幅での扱いも含めて見直す） |
| R 17 | 低 | 発売予定は楽天ブックス書籍検索 API に依存する（API の仕様変更・認証方式の変更で取得できなくなる。2026 年にアクセスキー必須・Referer 必須に変わった）。巻の判定は商品名と作品名の照合なので、作品名が書名と違うと「該当なし」、似た書名の外伝などが巻として拾われる可能性がある。楽天に載るのは予約開始（発売の 1〜2 か月前）から | 取得処理は `ReleaseService.js` の `fetchRakutenBooks` / `parseRakutenVolume` にまとめてあるので、仕様が変わったらここを直す。拒否されたら DEVELOPMENT.md の楽天の設定を確認。該当なしは作品名を書名に合わせる（作品ごとの検索キーワードは 6.5 の候補） |
| R 16 | 低 | 今期のアニメは外部サービス Annict に依存する（サービス終了・API の仕様変更で取得できなくなる）。Annict の期はその期に始まった作品のため、前の期から続く 2 クール目以降の作品は今期の一覧に出ない。登録済みかどうかは期名とタイトルの一致で判定するため、期名を変えて登録すると「未登録」のまま表示される | 取得処理は `AnimeSeasonService.js` の `fetchAnnictWorksPage` / `toSeasonWork` にまとめてあるので、取得元を変えるときはここを差し替える。続いている作品は [◀ 前の期] で確認する。判定がずれるときは Annict の作品 ID を期に持たせる（列の追加）を検討 |
